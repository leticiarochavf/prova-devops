## modelo
O projeto ira utilizar o modelo github flow, mantem a branch main como principal e qualquer mudança criar uma nova branch para alteração 

## fluxo
main - nova branch (caso de mudanças sem alterar o principal) - alterar- revisar - merge- main 

## Branch
Cada branch deve ter um nome para o que for feito ex: alterar-titulo, adicionar-imagem

## atualização
Antes de iniciar uma nova atividade, o integrante deve atualizar a main para garantir que possui a versão mais recente do projeto

## revisão
Antes de colocar o que foi feito na main, deve revisar se esta funcionando, sem erros aparentes, o codigo está correto e se a tarefa realmente foi realizada

## Commit
Todo commit deve seguir um padrão tipo(escopo opcional): descrição. Deve ser feito com mensagens claras e objetivas, o commit deve ser escolhido de acordo com a função desejada

## Conflitos
Se der conflito entre duas branches, a gente confere o que cada uma mudou e escolhe qual parte vai ficar. Depois arruma o arquivo, salva e termina o merge.

## Reversão
Se alguma alteração der errado, vamos reverte´la sem peder os commits anteriores
